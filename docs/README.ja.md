# NeoDhizuku

[Dhizuku](https://github.com/iamr0s/Dhizuku) のフォーク版です。デバイスオーナー（DeviceOwner）権限を他のアプリに制御された形で共有します。

---

## ⚠️ 未完成に関する警告

**現在開発中のバージョンです。日常利用の端末や本番環境では使用しないでください。**
一部の機能は実装されたばかりで、一部は実機での検証が不十分です。パッケージ名は `com.neodhizuku.more` に変更されており、公式版とは**共存できません**（異なるデバイスオーナーになります）。まずはテスト端末で検証してください。公式版とのデータ互換性はありません。移行前に必ずバックアップしてください。

## 1. 改変内容と新機能

すべての変更は `NeoDhizuku.UseNeoDhizuku` のマスタースイッチ配下にあります（`app/src/main/java/com/neodhizuku/more/NeoDhizuku.kt`）。

> `false` にするとすべての個別機能が無効になり、動作は**完全に上流の元実装にフォールバック**します。個別機能を単独で無効にすることもでき、比較デバッグに便利です。

### 基本情報

| 項目 | 上流 | 本プロジェクト |
|---|---|---|
| パッケージ名 | `com.rosan.dhizuku` | `com.neodhizuku.more` |
| アプリ名 | Dhizuku | NeoDhizuku |
| 対応 Android | Android 8.0+（コンパイル対象 API 37） | 同上 |

> Manifest 内の API 権限名と AIDL パッケージ名は**そのまま維持**されています。これは既存のサードパーティクライアントが変更なしで本アプリを認識できるようにするためです。

### セキュリティ強化

- **認可エントリがクライアント申告の UID を信頼しなくなりました**: サーバー側が `Binder.getCallingUid()` で実際の身元を取得し、ワンタイムトークン（有効期間 10 分）を発行します。Activity が検証を通過した後にのみその UID を承認します。旧版クライアントは互換パスを通り、既存の認可を上書きしません。
- Provider の認証、`remoteProcess` コマンドの監査、起動時の自己署名検証。
- 署名ホワイトリストは**ビルド時**に注入され、未設定の場合は自動的にスキップされます。自分でビルド・デバッグする際に便利です。

### UI の再構築

KernelSU マネージャーのレイアウト思想を参考に、Material3 で実装しています（**miuix / coui は未使用**）:

- **フローティングボトムナビゲーション**: 4 ページで共通、アイコン + テキスト、**絵文字なし**。未アクティブ時は「ホーム / 設定」のみ表示。サブページではバーを非表示。
- **ホーム状態カード**: アクティブ後は「左側に状態カード + 右側に上下 2 枚の小カード」——チェックアイコン + アクティブ済み + オーナータイプ + バージョン番号（タップでアクティブ化ページへ）、右上に認可アプリ数、右下にサービス稼働時間（`HH:MM:SS`、サービス再起動でリセット）。**未アクティブ時は上流の元デザインを維持**します。
- **アプリ管理**: タブなし。Dhizuku 関連のアプリはすべて同一リストに表示され、スイッチが認可状態を直接示します。マニフェストに権限を宣言していないが呼び出しを行ったアプリ（一部のインストーラーなど）は自動的に登録され、そのまま認可できます。
- **ブラックリスト専用ページ**: アプリ管理から分離。個別に解除可能。
- **認可ダイアログ**: プログレスバーなし。「許可」は薄い緑、「拒否」は赤で強調、「ブラックリストに追加」は黒、いずれも背景枠のないプレーンテキスト。カウントダウンは小さい文字でボタン行の下に配置。
- **呼び出し履歴**: 各アプリがどの機能を呼び出したかを記録し、すべて短い中国文で記述します。**永続化保存、既定で 30 日間保持**。各レコードには当時のサーバー側稼働ログ断片が付随します。別途「稼働ログ」タブがあり、サーバー自身のログを**未アクティブ時でも**閲覧できます。
- **サービスの開始/停止**: 右上ボタンは稼働中はバツ印、停止後は再起動アイコンに変化。稼働時間カードは停止時に赤一色で「サービス拒否」と表示します。停止後も認可と呼び出し履歴の閲覧は維持され、それ以外の操作はすべて拒否されます。
- **デバイスオーナー移行の遮断**: 認可を得たサードパーティアプリは `binderWrapper` 経由でデバイスオーナーとして DPM の任意のメソッドを呼び出せます。認可を戻す手段を提供しない場合、移行後にオーナーを取り戻せません。設定項目「サードパーティアプリによるデバイスオーナー移行を許可」は**既定で無効**、無効時は直接拒否して通知を発行します。
- **サービスポリシーページ**: 設定内の 2 階層メニュー。API サービスのマスタースイッチ、ホワイトリストモード、サービス停止後の処理方法、デバイスオーナー移行スイッチを一元的に管理します。
- **アカウント削除不要の一時アクティブ化**: 上流の「先に全アカウントを削除しなければならない」という要件を不要にしました。後述の専用セクションを参照してください。
- **テーマページ**: ダークモード 4 段階（システムに従う / ライト / ダーク / ダーク純黒 AMOLED）+ 動的配色スイッチ。ダークモードは折りたたみ式セレクタ。
- **設定ページ**: 「管理」セクションのエントリを追加、**未アクティブ時はセクション全体を非表示**。
- **アクティブ化エラー表示**: 英語の生エラーを中国語の原因 + 対処案 + コピー可能な診断情報にマッピングします。

### デバッグログ

TAG は `NeoDhizuku` に統一され、分類サブタグ（`Nav` / `Theme` / `Perm` / `Home` / `Apps` / `Daemon` / `Server` / `Activate` / `UI` / `Boot`）を持ちます。スイッチは `NeoDhizuku.DebugLog`。オフ時は完全に無音で、文字列連結のコストも発生しません。

```bash
adb logcat -s NeoDhizuku:V              # すべて
adb logcat -s NeoDhizuku:V | grep Nav   # ナビゲーションのみ
```

## 2. 注意事項と使い方

### アクティブ化

上流と同様に、Shizuku、ADB、アカウント削除不要モードでデバイスオーナーになれます。
**上流の注意書きに従ってください: アカウントが一切ない状態の端末での設定が推奨されます。**既にアカウントがある場合は、先に削除する必要があるかもしれません。

デバイスオーナーになった後、サードパーティアプリは Dhizuku API 経由でデバイスオーナー権限の利用を申請できます。

### アカウント削除不要の一時アクティブ化

上流では**アカウントが一切ない状態**での設定が推奨され、そうでない場合は先に削除が必要です。本方式はこの制限を回避します。

**原理**: `DevicePolicyManagerService` において、アカウントチェック `hasIncompatibleAccountsOrNonAdb` は `isAdb` 分岐内でしか読み込まれません。オリジナル版は ADB（`dpm set-device-owner`）経由、すなわち `isAdb=true` で 3 つのゲートすべてが評価されます。本方式は**アプリ自身の uid** で直接呼び出すため `isAdb=false` となり、`hasUserSetupCompleted` のみが検証され、**アカウントは一切読み込まれません**。

**7 ステップ**:

| ステップ | 実行者 | 内容 |
|---|---|---|
| ① | shell | `cmd role set-bypassing-role-qualification true` |
| ② | shell | `cmd role add-role-holder --user 0 android.app.role.DEVICE_POLICY_MANAGEMENT <pkg>` |
| ③ | shell | `settings put secure user_setup_complete 0` |
| ④ | アプリ自身 | リフレクションで `forceUpdateUserSetupComplete(0)` を呼び、③の値を DPM のメモリ状態に反映 |
| ⑤ | アプリ自身 | リフレクションで `setActiveAdmin` |
| ⑥ | アプリ自身 | リフレクションで `setDeviceOwner` |
| ⑦ | shell | `settings put secure user_setup_complete 1` |

③ と ④ は**必ず対で実行**してください。③のみでは無効で、メモリ状態が変わらずゲートは閉じたままです。④ の引数は状態値ではなく userId で、Settings の実際の値をメモリに双方向にコピーします。そのため③は省略できません。

**3 つの前提条件**:

- Shizuku または root 権限（①③⑦ の shell コマンド実行に必要。通常アプリは `WRITE_SECURE_SETTINGS` を取得できません）
- Android 13（API 33）以上（`DEVICE_POLICY_MANAGEMENT` ロールはこのバージョンで導入されました）
- まだデバイスオーナーになっていないこと

**副作用**: フラグが 0 の間、3 ボタンナビゲーションのホームキーと履歴キーが動作しなくなります（戻るキーは動作、ジェスチャーナビゲーションは影響なし）。コードは `finally` ブロックで必ず復元するため、端末が「セットアップ未完了」状態のままになることはありません。

**トラブルシューティング**: ロールコマンドが `RC=0` を返しても権限が DENIED のままの場合、多くはマニフェストに `MANAGE_DEVICE_ADMINS` / `MANAGE_PROFILE_AND_DEVICE_OWNERS` が宣言されていないことが原因です。これらは signature レベルの権限で、事前に宣言されていないとシステムはロール付与時に許可しません。ページにこのヒントが直接表示されます。

セットアップウィザードが復元されていない場合、ページは赤いヒントを表示し、最初の 2 ステップを無効化して「手動復元」のみを残します。

### 認可管理

- サードパーティアプリの初回呼び出し時に認可リクエストが表示され、許可・拒否・ブラックリスト追加を選択できます。
- **ブラックリスト追加後、そのアプリの認可リクエストは処理されなくなります。**
- 「アプリ管理」ではいつでも各アプリの認可を切り替えられます。「ブラックリスト」ページで解除できます。
- **ホワイトリストモード**を有効にすると、ホワイトリスト内のアプリのみが高リスクインターフェースを呼び出せます。

### スイッチの使い方

`NeoDhizuku.kt` を編集します:

```kotlin
const val UseNeoDhizuku: Boolean = true   // マスタースイッチ、false = すべて上流の動作にフォールバック
const val UseThemePage: Boolean = true    // 個別機能: テーマページ
const val DebugLog: Boolean = true        // 個別機能: デバッグログ
```

問題の切り分け方: まず `UseNeoDhizuku = false` でベースラインをビルドし、`true` に切り替えて比較してください。特定の個別機能に問題があれば、それだけをオフにして特定します。

### サービスポリシー

設定 →「サービスポリシー」、3 つのセクション:

**① API サービス**: マスタースイッチ（他のアプリによる API サービスの利用を許可）、ホワイトリストモード（ホワイトリスト内のアプリのみに API サービスの利用を許可）。

**② サービス停止後の処理方法**（折りたたみ式セレクタ。サービス停止後にのみ有効）:

| オプション | 動作 |
|---|---|
| 危険なサービスを拒否し失敗を返す | サービスは検出可能、非読み取り操作はすべて拒否 |
| 危険なサービスを拒否し成功を返す | 通過させるが実際には実行せず、成功のみ返す |
| サービスを完全に拒否し失敗を返す | null を返し、他のアプリからサービスが見えなくなる |
| サービスを完全に拒否し成功を返す | 空の結果を返す |
| 何もしない | 認可リクエストを保留し、クライアントは無期限に待機 |

「何もしない」はスレッドをブロックするのではなく**コールバックを呼ばない**ことで実現しているため、他の呼び出しの処理には影響しません。

**③ デバイスオーナー移行**: 前述「デバイスオーナー移行の遮断」のスイッチです。

### 既知の制限

- フローティングボトムバーはスワイプでページを切り替える Pager 構造になっておらず、タップでのみ切り替えられます。
- テーマは Material3 ネイティブの `dynamicColorScheme`（Android 12+ でシステムが対応）を使用しており、サードパーティの配色ライブラリは導入していません。
- **公式 Dhizuku と共存している場合**: 公式パッケージの authority をハードコードしているクライアント（amarok、爱玩机工具箱 など）は本アプリではなく公式版に接続し、「公式版のダイアログが出て本アプリが応答しない」という現象が発生します。ContentProvider の authority はグローバルに一意で奪取できないため、解決策は公式版をアンインストールして `neoCompat` または `official` フレーバーに切り替えることです。
- **アカウント削除不要のアクティブ化は Android 13+ のみ対応**です。それ未満ではページに「非対応」と表示され、ステップが隠されます。
- Shizuku API 14 では `newProcess` が削除されます。その時点で、このアクティブ化経路の shell 実行を User Service に移行する必要があります。

## 3. ビルド方法

### 必要環境

Android Studio **Quail 4（2026.1.4）** 以上（AGP 9.4.1 の最低要件）、JDK 21。
SDK Manager で SDK Platform 37、Build Tools 37.0.0、NDK 29.0.14206865 をインストールしてください。

### ビルド

プロジェクトには 3 つのフレーバー（product flavor）があります。`namespace` とソースのパッケージ名は `com.neodhizuku.more` に固定されており、
`applicationId` と provider の authorities のみがフレーバーによって変わります:

| フレーバー | applicationId | 公式版 authority を登録 | 公式 Dhizuku と共存 | 公式パッケージをハードコードしたクライアントに対応 |
|---|---|---|---|---|
| `neo` | `com.neodhizuku.more` | いいえ | **可能** | いいえ |
| `neoCompat` | `com.neodhizuku.more` | はい | 不可 | **はい** |
| `official` | `com.rosan.dhizuku` | — それ自体が公式 | 不可（同一パッケージ） | **はい** |

`neo` と `neoCompat` は applicationId が同じため同時にはインストールできませんが、比較テスト用に両方ビルドしておくことはできます。

```
./gradlew assembleNeoDebug        共存版（日常利用に推奨）
./gradlew assembleNeoCompatDebug  引き継ぎ版（先に公式 Dhizuku をアンインストール）
./gradlew assembleOfficialDebug   公式パッケージ版（先に公式 Dhizuku をアンインストール）

./gradlew assembleBothDebug       neo + neoCompat の 2 つを一度にビルド
./gradlew assembleAllDebug        3 つすべてを一度にビルド
```

リリース版は `Debug` を `Release` に置き換えてください（3 つまとめての `assembleAllRelease` もあります）。

> **重要**: デバイスオーナーは同時に 1 つのパッケージにしか所属できません。`neoCompat` / `official` はどちらも
> **先に公式 Dhizuku をアンインストール**する必要があります。そうしないと provider authority が衝突して
> インストールに失敗します（`INSTALL_FAILED_CONFLICTING_PROVIDER`）。インストール後は再アクティブ化が必要です。

リポジトリ内は既定でデバッグ署名（`keystore/`）です。配布前に必ず自分の署名設定に置き換えてください。
