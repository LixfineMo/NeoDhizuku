# NeoDhizuku

[Dhizuku](https://github.com/iamr0s/Dhizuku) をベースにした二次開発版です。デバイスオーナー（DeviceOwner）権限を制御された形で他のアプリに共有します。

## 特徴

### アクティベーション

- **アカウント削除不要のアクティベーション**：上流の「事前に全アカウントを削除」という要件が不要になりました（Shizuku / root + Android 13 以降が必要）
- **デバイス管理者モード**：システム設定から付与でき、ハードルは最も低いですが、サードパーティクライアントは初期化できません（既知の制限を参照）
- **アクティベーションエラーの表示**：英語の生エラーを原因と対処法の日本語に変換し、診断情報をワンタップでコピーできます

### セキュリティ

- **認証エントリはクライアント申告の UID を信用しません**：サーバー側で `Binder.getCallingUid()` により実際の身元を取得し、使い捨てトークン（10 分有効）を発行します
- **デバイスオーナー譲渡のブロック**：既定で無効、拒否時に通知を送信します
- **消去の強制確認**：`wipeData` は常に遮断し、2 段階の警告と責任確認のチェックが必要です。許可は一度きりで 5 分間有効です
- Provider の認証、`remoteProcess` コマンドの監査、起動時の自己署名検証

### インターフェース

KernelSU マネージャーのレイアウトを参考に、Material3 で実装しています（**miuix / coui は不使用**）：

- **フローティングボトムバー**：4 ページで共通、アイコン + テキスト、絵文字なし。ページは左右スワイプでも切り替え可能。サブページでは非表示
- **ホームのステータスカード**：有効時は「左にステータスカード + 右に小さなカード 2 枚」——有効状態 + 種別 + バージョン、右上に認証済みアプリ数、右下にサービス稼働時間
- **アプリ管理**：関連アプリを 1 つのリストに集約、スイッチが認証状態を直接表示。権限を宣言せずに呼び出したアプリも自動登録されます
- **ブラックリスト専用ページ**：個別に解除可能
- **認証ダイアログ**：進捗バーなし。「許可」は薄い緑、「拒否」は赤で強調、「ブラックリスト」は黒。カウントダウンはボタン行の下に小さく表示
- **呼び出し履歴**：各アプリが使った機能を**引数付きの分かりやすい表現**で記録。30 日間保存し、各エントリにサーバーログの断片を添付。「実行ログ」タブもあります
- **サービスの開始 / 停止**：停止中は稼働時間カードが全体赤の「サービス拒否」表示に。認証と呼び出し履歴の閲覧は可能
- **テーマページ**：ダークモード 4 段階（システムに従う / ライト / ダーク / AMOLED の純黒）+ 動的配色。動的配色を無効にすると内蔵カラーパレットが選べ、リキッドグラスのボトムバー切り替えもある
- **概要ページ**：動くアイコン、バージョンと端末情報、GitHub / QQ への導線、更新チェック（プレリリース受信トグル付き）

### サービス（設定 → サービス）

| セクション | 内容 |
|---|---|
| API サービス | マスタースイッチ、ホワイトリストモード、旧互換バージョンを使用（既定でオン） |
| サービス停止時の動作 | 5 択のドロワー。サービス停止後にのみ有効 |
| デバイスオーナー譲渡 | 上記の譲渡ブロックのスイッチ |

「旧互換バージョンを使用」は、クライアントに返すバージョン名を切り替えます。オン（既定）では上流の `2.12.0` を返します（バージョンを検証するクライアントがあるため）。オフでは本プロジェクト自身のバージョン名を返します。

サービス停止時の動作：

| 選択肢 | 動作 |
|---|---|
| 危険なサービスを拒否して失敗を返す | サービスは検出可能、読み取り以外はすべて拒否 |
| 危険なサービスを拒否して成功を返す | 通過させるが実行せず、成功のみ返す |
| サービスを完全に拒否して失敗を返す | null を返し、他アプリからは検出できない |
| サービスを完全に拒否して成功を返す | 空の結果を返す |
| 何もしない | リクエストを保留し、クライアントは無限に待機 |

「何もしない」はスレッドをブロックするのではなく**コールバックしない**ことで実現しているため、他の呼び出し処理には影響しません。

## 使い方

### アクティベーション

Shizuku、ADB、アカウント削除不要モードに対応しています。デバイスオーナーになると、サードパーティアプリが Dhizuku API 経由でデバイスオーナー権限を要求できるようになります。

### アカウント削除不要のアクティベーション

上流では**端末にアカウントがない状態**での設定が推奨されていますが、本フォークは ADB 経由ではなくアプリ自身の uid で直接呼び出すため、この制限を回避しています。システムは `hasUserSetupCompleted` のみを検証し、アカウントを一切読みません。

**前提条件**：Shizuku または root 権限、Android 13（API 33）以降、まだデバイスオーナーになっていないこと。

**副作用**：0 に設定している間、3 ボタンナビゲーションのホームと履歴キーが効かなくなります（戻るキーは有効、ジェスチャーナビゲーションは影響なし）。コードは `finally` で必ず復元します。

### 認証の管理

- サードパーティアプリの初回呼び出し時に認証ダイアログが表示され、許可・拒否・ブラックリストを選択できます
- **ブラックリストに入れると、そのアプリの認証リクエストは処理されなくなります**
- 「アプリ管理」でいつでも認証を切り替え、「ブラックリスト」ページで解除できます
- **ホワイトリストモード**を有効にすると、ホワイトリスト内のアプリのみが高リスク API を呼び出せます

## 既知の制限

- リキッドグラスは半透明の重ね描画であり、リアルタイムの背景ぼかしではありません（Compose に背景ぼかしの API がないため）
- **デバイス管理者モードではサードパーティアプリが初期化できません**：クライアントの `Dhizuku.init()` はデバイスオーナーとプロファイルオーナーしか受け付けず、デバイス管理者は即座に失敗します。このコードはサードパーティのプロセスで動くため、本アプリからは影響できません
- アカウント削除不要のアクティベーションは Android 13 以降のみ対応
- USB デバッグを有効にしているとシステム設定画面が開けなくなることがあります。adb を無効にすれば復旧します
- Shizuku API 14 で `newProcess` が削除されるため、それまでに User Service への移行が必要です

## ビルド

Android Studio **Quail 4（2026.1.4）** 以降（AGP 9.4.1 の最小要件）、JDK 21。SDK Platform 37、Build Tools 37.0.0、NDK 29.0.14206865 をインストールしてください。

```
./gradlew assembleDebug      デバッグ版
./gradlew assembleRelease    リリース版
```

出力は `app/build/outputs/apk/debug/` にあります。

パッケージ名は `com.neodhizuku.more` に固定され、さらに公式の authority `com.rosan.dhizuku.server.provider` も登録しているため、公式パッケージ名をハードコードしているクライアント（amarok、爱玩机工具箱 など）も本アプリに接続できます。

リポジトリ同梱の署名はデバッグ用（`keystore/`）です。配布前に自分の署名設定へ置き換えてください。
