# NeoDhizuku

把设备所有者（DeviceOwner）权限安全地共享给其他应用。

> 🧪 表示仍在测试、默认关闭或尚未集成，行为可能变化。

## 相比原版的新特性

### 已可用

- **兼容原版客户端**：额外注册官方 provider authority 与授权 action，硬编码官方包名的应用（Hail、爱玩机工具箱等）可直接接入。
- **单项系统接口配置**：在「设置 - 服务」里按应用单独开关 86 项设备策略能力（禁用摄像头、锁屏、隐藏应用、清除数据、擦除设备…）。未配置的应用跟随全局策略，配置过的自动置顶并显示已允许数量；被拦时发通知，日志显示中文接口名。
- **客户端 API 版本识别**：授权弹窗显示 `old` / `modern-N` 药丸，按版本分流，旧版 API 不会被新版逻辑误拦截。
- **能力分级与强制确认**：区分设备管理员 / 资料所有者 / 设备所有者三级；擦除数据、转移所有者单独拦截，擦除需三次确认。
- **拒绝服务与能力不足处理**：五种拒绝模式、三种能力不足模式，可静默成功、返回失败或完全不响应。
- **调用记录与运行日志**：落库保留 30 天，按天 / 应用 / 秒分组，调用发生时截取日志片段一起留痕。
- **权限委派管理**：可读、可改、可清空委派给其他应用的 scopes。
- **白名单与严格校验**：记录加入时的签名指纹，可选严格模式。
- **界面**：主题页可切换「原版 / miuix」两套 UI 引擎，miuix 卡片与下拉带按压缩放反馈；悬浮底栏（常规 / 液态玻璃）、两种引擎都生效的卡片模糊、背景图裁切 / 平移 / 缩放、纯黑模式、动态取色、自定义种子色、关于页液态波浪图标与鸣谢。
- **更新与反馈**：启动时从官网检查更新（更新设置里可关闭）、四个官方域名自动切换、按服务端返回的相对地址下载；应用内与官网都能提交反馈。
- **转移设备所有者**：第三方发起的转移由一个开关控制；应用内转移始终两道确认，弹窗显示目标应用图标、名称、包名与警告文案。
- **模块**：Xposed 配置页常驻服务板块，始终跟随框架作用域，不需要在应用内勾选目标应用。
- **稳定性**：不在多任务显示管理器、划卡后自启一次、设备身份状态与「清除残留身份」、34 个语言目录（未完整翻译的条目回退英文）。

### 🧪 测试中 / 尚未集成

- 免删账号临时激活：仅 Android 13+ 且需 Shizuku 或 root；会临时改动 `user_setup_complete`，中断需手动恢复。
- 实验性功能页四项：免删激活缺陷修复、权限委派残留清理、完整运行日志、严格白名单校验，默认全部关闭。
- 调试分区：实时参数修改、详细运行信息、服务配置修改、重置 NeoDhizuku，会直接改内存变量与私有配置。
- 液态玻璃折射依赖 `RuntimeShader`，仅 Android 13（API 33）及以上可见。底栏药丸只折射底栏层与上下露出的背景，保持通透、不放大内容，松手有阻尼回弹。
- Modern 版 API（事务码 0–16 兼容原版）尚未发布。
- LSPosed / LSPatch 模块（DAX 化转发）仍为独立方案与工程，未集成进主应用。
- 被改过包名的实例：身份移除 / 转移工具已就位，界面入口未接。

## 是什么

参考 Shizuku 的思路，把本应用持有的设备所有者权限借给其他应用。第三方拿到 binder 后可调用设备策略接口，全部调用都经过授权记录、接口策略、能力分级与审计。

## 支持版本

Android 8.0（API 26）~ Android 17（编译目标 API 37）。

## 激活

打开应用，在首页「激活」里按向导选择设备管理员、Shizuku / ADB，或（Android 13+）免删模式。传统方式建议设备上没有账户；免删模式不需要清账户。步骤与风险提示都在应用内向导与官网激活说明里。

## 更新与反馈

每次打开会从官网查一次更新，有更新才在首页顶部显示一张卡片，不弹窗。更新设置里可关闭自动检查、切换来源、设置自定义清单地址。关于页底部与官网导航 / 页脚都能提交意见反馈，只收集不展示。

## 致开发者

第三方应用通过 Dhizuku-API 取得 binder 后即可调用；本应用会按「授权记录 → 单项接口策略 → 白名单 → 严格校验 → 签名」的顺序判定，被拒绝时给出通知与可读日志。完整接入示例、调用结果约定与特殊情况处理规范见官网「开发者文档」。
