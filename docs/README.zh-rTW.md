# NeoDhizuku

基於 [Dhizuku](https://github.com/iamr0s/Dhizuku) 的二次開發版本，把裝置擁有者（DeviceOwner）權限受控地分享給其他應用程式。

## 功能特色

### 啟用

- **免刪帳號暫時啟用**：免去上游「必須先移除全部帳號」的要求（需 Shizuku / root + Android 13 以上）
- **裝置管理員模式**：從系統設定即可授予，門檻最低，但第三方用戶端無法初始化（見已知限制）
- **啟用錯誤提示**：英文原始錯誤對應為中文原因 + 處理建議 + 一鍵複製診斷資訊

### 安全性

- **授權入口不再信任用戶端自行回報的 UID**：改由伺服端用 `Binder.getCallingUid()` 取得真實身分並簽發一次性權杖（10 分鐘有效）
- **裝置擁有者轉移攔截**：預設關閉，拒絕時發出通知
- **清除裝置強制確認**：`wipeData` 一律攔截，需兩層警告 + 勾選責任聲明才放行；放行一次性且 5 分鐘內有效
- Provider 鑑權、`remoteProcess` 命令稽核、啟動時自我簽名校驗

### 介面

參考 KernelSU 管理端的配置思路，以 Material3 實作（**未引入 miuix / coui**）：

- **懸浮底部導覽列**：四頁共用，圖示 + 文字，不使用 emoji；四頁可左右滑動切換，也可點擊底欄跳轉；子頁面不顯示
- **首頁狀態卡**：啟用後為「左側狀態卡 + 右側上下兩張小卡」——已啟用 + 身分類型 + 版本號，右上授權應用程式數，右下服務執行時間
- **軟體管理**：所有相關應用程式都在同一清單，開關直接顯示授權狀態；未宣告權限但曾發出呼叫的應用程式會自動登記
- **黑名單獨立頁面**：可逐項解除封鎖
- **授權彈窗**：無進度條；「允許」淺綠、「拒絕」紅色強調、「加入黑名單」黑色；倒數小字置於按鈕列下方
- **呼叫記錄**：記錄各應用程式使用了哪些能力，**口語化描述並帶參數**；持久化保存 30 天，每筆記錄附帶伺服端記錄片段；另含「執行記錄」分頁
- **服務啟停**：停止後執行時間卡整卡純紅顯示「拒絕服務」，仍可檢視授權與呼叫記錄
- **主題頁**：深色模式四段（跟隨系統 / 淺色 / 深色 / AMOLED 純黑）+ 動態取色；關閉動態取色後可用內建取色板，另含液態玻璃底欄開關
- **關於頁**：動態圖示、版本與裝置資訊、GitHub / QQ 入口、更新偵測（含灰階更新開關）

### 服務（設定 → 服務）

| 分區 | 內容 |
|---|---|
| API 服務 | 總開關、白名單模式、使用舊的相容版本號（預設開啟） |
| 關閉服務後的處理方式 | 五選一抽屜，僅在服務被關閉後生效 |
| 裝置擁有者轉移 | 上述轉移攔截的開關 |

「使用舊的相容版本號」決定回傳給用戶端的版本名稱：開啟（預設）時回傳上游的 `2.12.0`——部分用戶端會校驗版本；關閉時回傳本專案自身的版本名稱。

關閉服務後的處理方式：

| 選項 | 行為 |
|---|---|
| 拒絕危險服務並回傳失敗 | 可查詢到服務，非唯讀操作一律拒絕 |
| 拒絕危險服務並回傳成功 | 放行但不實際執行，只回成功 |
| 完全拒絕服務並回傳失敗 | 回傳 null，其他應用程式查不到服務 |
| 完全拒絕服務並回傳成功 | 回傳空結果 |
| 不做任何處理 | 擱置請求，用戶端無限等待 |

「不做任何處理」是透過**不回呼**實作而非阻塞執行緒，不影響服務處理其他呼叫。

## 使用方式

### 啟用

支援 Shizuku、ADB、免刪帳號模式。成為裝置擁有者後，第三方應用程式即可透過 Dhizuku API 申請使用裝置擁有者能力。

### 免刪帳號暫時啟用

上游建議在**裝置上沒有任何帳號時**設定，本方案繞開了這項限制：以應用程式自身 uid 直接呼叫而非走 ADB 分支，系統只校驗 `hasUserSetupCompleted`，完全不讀取帳號。

**前提**：Shizuku 或 root 權限、Android 13（API 33）以上、尚未成為裝置擁有者。

**副作用**：設為 0 期間，三鍵導覽的首頁與最近工作鍵會失效（返回鍵可用，手勢導覽不受影響）。程式碼在 `finally` 中必定恢復。

### 授權管理

- 第三方應用程式首次呼叫時彈出授權請求，可允許、拒絕或加入黑名單
- **加入黑名單後不再處理該應用程式的授權請求**
- 「軟體管理」中可隨時開關授權；「黑名單」頁可解除封鎖
- **白名單模式**開啟後，僅白名單內的應用程式可呼叫高風險介面

## 已知限制

- 液態玻璃底欄為半透明疊加效果，非即時背景模糊（Compose 無原生背景模糊介面）
- **裝置管理員模式下第三方無法初始化**：用戶端 `Dhizuku.init()` 只認可裝置擁有者 / 設定檔擁有者，裝置管理員會直接回傳失敗。該程式碼跑在第三方行程，本應用程式無法影響
- 免刪帳號啟用僅支援 Android 13 以上
- 開啟 USB 偵錯時可能出現系統設定頁無法開啟，關閉 adb 即恢復
- Shizuku API 14 將移除 `newProcess`，屆時免刪啟用需移轉至 User Service

## 建置

Android Studio **Quail 4（2026.1.4）** 以上（AGP 9.4.1 的最低要求），JDK 21。需安裝 SDK Platform 37、Build Tools 37.0.0、NDK 29.0.14206865。

```
./gradlew assembleDebug      除錯版
./gradlew assembleRelease    發行版
```

產物位於 `app/build/outputs/apk/debug/`。

套件名稱固定為 `com.neodhizuku.more`，同時註冊官方 authority `com.rosan.dhizuku.server.provider`，讓硬編碼官方套件名稱的用戶端（amarok、爱玩机工具箱等）也能連到本應用程式。

儲存庫內預設為除錯簽章（`keystore/`），正式散布前請替換為自己的簽章設定。
